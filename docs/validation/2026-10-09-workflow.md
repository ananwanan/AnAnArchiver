# GitHub Actions repair — 2026-10-09

Historical source note (2026-10-17): this report records the former libarchive
fork and its validation only. Current dependency initialization uses the official
[libarchive/libarchive](https://github.com/libarchive/libarchive) latest stable
release. The fork branch and revision below remain historical evidence; they are
not the current dependency source or proof of official-release validation.

The [main workflow run](https://github.com/ananwanan/AnAnArchiver/actions/runs/37924122086)
initially failed in all five jobs before configuration. The application referenced
libarchive commit `0a6ff818eefd3f13a941ccf6994bcf72cdc122bb`, but that existing ZIP
abort cleanup fix had never been published to the backend remote. Git reported
`upload-pack: not our ref`.

At the time of this validation, the commit was available on the former fork's
[`codex/zip-abort-cleanup`](https://github.com/ananwanan/libarchive/tree/codex/zip-abort-cleanup)
branch. An isolated empty repository successfully fetched the exact commit with
`--depth 1`. Retrying the workflow passed dependency initialization in every job;
Windows, GCC and ASan/UBSan then passed their complete Core suites.

Two further failures were exposed by that retry:

- Clang 18 with libc++ 18 requires `-fexperimental-library` for `std::stop_token`
  and `std::jthread`, as documented in the [LLVM 18 libc++ guide](https://releases.llvm.org/18.1.8/projects/libcxx/docs/UsingLibcxx.html).
  The workflow now passes this flag through configuration, compilation and linking.
  CMake checks thread API compilation and runtime linkage with `Threads::Threads`
  before building dependencies; the Android experimental-library fallback remains.
- libarchive deliberately exposes NFD UTF-8 archive names on Apple platforms
  (`archive_string.c`, also exercised in its
  [historical fork ZIP filename tests](https://github.com/ananwanan/libarchive/blob/0a6ff818eefd3f13a941ccf6994bcf72cdc122bb/libarchive/test/test_read_format_zip_filename.c)).
  Unicode fixtures now expect that exact representation. Compression tests still
  compare all names, directories, ordering and streamed payload bytes; the native
  destination check still requires exactly one final file. Production filename
  handling is unchanged.

Before publishing the application fix, the MSVC Core application suite passed all
five CTest groups. The modified compression suite also passed with MinGW GCC 16,
and `git diff --check` passed. macOS and Clang 18 validation is provided by the
GitHub workflow triggered by the application fix, not by Windows host results.
