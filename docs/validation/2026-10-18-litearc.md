# 2026-10-18：轻匣 / LiteArc 改名与构建版本显示

## 产品名称与升级兼容

正式中文名为“轻匣”，英文名为 LiteArc。窗口、帮助/关于页、命令行显示、
安装器、系统菜单、Linux desktop 文案、macOS bundle、Android 显示名和分发
文件名已同步。需求文档 `AGENTS.md`、README、平台打包说明和架构文档同步
记录这一决定；历史验证记录保留当时真实的产物名，并注明改名前的背景。

可执行文件和分发包使用 `LiteArc.exe`、`LiteArc.app`、`LiteArc.sh` 和
`LiteArc-<version>-<platform>-<arch>`。现有源码仓库地址、C++ namespace、
公开头文件目录、CMake target/选项、QML URI、设置身份、安装器 AppId、
系统关联 ID 和 `share/AnAnArchiver` 保留，以兼容现有设置、依赖构建与升级。
主 CMake project 名称为 LiteArc，内部 executable target 仍为 AnAnArchiver。

安装升级只迁移指向同一安装目录旧程序的命令和快捷方式。用户自建内容、
其他程序的快捷方式及 COM handler 会保留。快捷方式清理从文件系统根开始
逐级检查路径，跳过 junction/reparse 路径；删除前再次检查。

## 开源组件版本来源

`scripts/write_frontend_build_info.py` 在依赖验证通过后读取本次配置生成的
`dependency-build.json` 和 `build-trace-config.json`，将所用组件版本、完整
Git revision、来源类型和应用 Git revision/工作区修改标记嵌入程序。
这些记录与最终 provenance 共用构建输入，不在运行时读取开发机的源码目录，
也不会用当前子模块 HEAD 或示例版本冒充已使用的依赖。

帮助菜单的“开源组件与许可”显示应用版本、完整应用 revision，以及组件版本、
完整源码 revision 和所选 Qt 的运行时版本。源码 Qt 同时显示实际模块提交；
开发者 Qt kit、系统库和未选组件明确标记。已知 revision 的许可链接指向
对应提交，无法获知的开发者 kit revision 明确显示为未记录。

本次没有更新依赖或子模块，重新编译了当前应用。正式 Windows 包使用现有
完整源码 Qt 构建配置 `out/build/desktop-release-traced/application`，并保持
官方 libarchive 来源及已有补丁、版本/revision 和哈希追溯。

## 长安装路径的主机限制

本机在 303 字符安装目录、以及 313 字符的独立便携复制目录启动 GUI 时，
搜狗输入法组件触发 `C0000409 / FAST_FAIL_STACK_COOKIE_CHECK_FAILURE (0x2)`。
转储中的故障模块为：

`C:/Program Files (x86)/SogouInput/Components/IChat/1.0.2.3305/ichat_bundle64.dll`

该模块产品为搜狗输入法，版本 1.0.2.3305，位于应用包与 Qt 之外。转储栈上
出现长 EXE 路径覆盖。开发者 Qt 与完整源码 Qt 均可复现；仅执行 `--version`
成功，普通目录 GUI 启动成功。没有修改系统输入法、注入规则或全局配置。

`Test-Package.ps1 -MinimumInstallPathLength 0` 用于单独验证普通路径的实际
安装/升级/卸载，报告明确记录实际路径长度；默认值仍保留原有的 275 字符
最小路径构造要求。普通路径验收不能替代本机受阻的长安装路径 GUI 验收。
归档文件本身的 Unicode/长路径操作仍单独验证。

本次未运行 Linux/macOS/Android 主机或设备构建，未触发远程 CI 或发布。
MSIX 修改由输入验证回归覆盖，未提交 Microsoft Store。
