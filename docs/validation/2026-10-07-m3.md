## Delivered behavior

| Format | Offered method | Level |
| --- | --- | --- |
| ZIP | Deflate / Store | 1–9, default 6 / no level |
| 7z | LZMA2 / Store | 0–9, default 6 / no level |
| TAR | Store | No level |
| TAR.GZ | Gzip | 0–9, default 6 |
| TAR.BZ2 | Bzip2 | 1–9, default 6 |
| TAR.XZ | XZ | 0–9, default 6 |
| TAR.ZST | Zstandard | 1–22, default 3 |
| TAR.LZ4 | LZ4 | 1–9, default 1 |

The table describes the pinned build's exposed adapter options. Backend option
probes remove unavailable combinations, and filters requiring external helper
programs are excluded. ZIP and 7z default to Deflate and LZMA2. Password creation,
parallel-worker and configurable solid options are not exposed. Unsupported
password requests fail before input/output work.

Inputs are archived beneath their basenames; repeated selections and contained
descendants are deduplicated. Distinct selected hardlink names retain both entries.
Unrelated basename/path collisions are errors. Native identity checks preserve
separate selections in Windows case-sensitive directories. Input links/reparse
points and special files are rejected, rather than followed or silently omitted.
Output must be outside selected directories, cannot alias an input, and requires
an existing parent. Native paths containing NUL are rejected before filesystem IO.

Scanning retains bounded metadata and runs in a managed worker. Writing reuses a
128 KiB buffer and counts payload bytes separately from scan metadata. Finalization
has no fabricated percentage/ETA. The destination is atomically installed only
after backend close, flush and file close succeed. Explicit replacement consent
is required; precommit failure/cancellation preserves the original and removes
staging files. Late stops cannot report an already committed archive as cancelled.
Cleanup errors retain concrete diagnostics, including postcommit installed state.

Windows entry names use native wide strings; device prefixes are restricted to IO
boundaries rather than logical parent/relative-path operations. POSIX operations
temporarily select a worker-thread UTF-8 locale and restore it on every exit; the
global process locale is unchanged. Reader operations have the same method-local
guard, so a newly created Unicode archive also opens/extracts under a C locale.

Native directory cursors replace standard-library directory iteration. A concrete
MinGW 277-character-path reproduction showed the standard iterator returning
current-working-directory names as supposed children of the long input path.
The platform cursor uses FindFirst/FindNext on Windows and secured fdopendir/
readdir on POSIX, with an iterative bounded stack in the backend. The long-path
regression records expected names directly from its generator and compares actual
source/output bytes; it never accepts a library iterator's list as the sole oracle.

## Regression scope

Generated fixtures cover every advertised format/method, default and endpoint
levels, metadata and payload round-trips, Chinese/Japanese/Korean/emoji/accents,
Unicode destinations and paths beyond MAX_PATH, empty files/directories and a
24 MiB generated stream. They verify all creation phases, byte/entry totals,
callback/token cancellation, callback exceptions, source size/deletion/link
changes, entry/path/depth/metadata/byte/time budgets, invalid requests, aliases,
duplicate paths, replacement, destination races and installation failures.

Windows additionally tests native junction rejection, sharing violations during
atomic installation and optional NTFS case-sensitive directories. Optional native
symlink creation is feature-probed; an unavailable fixture reports the skip rather
than certifying that platform's symlink-creation coverage. Locale tests check
success/failure/cancellation and exact POSIX thread-locale restoration.

Application regressions verify worker execution, capability propagation, separate
scan/write counters, shutdown/cancellation, structured factory errors, commit/stop
races and a real create/open/extract Unicode round-trip. Production QML verifies
all eight format flows, native file/folder acceptance bindings, capability-driven
levels and explicit user level changes, GUI heartbeat responsiveness, phase/ETA
display, real 64 MiB ZIP cancellation with an existing output, errors and retry.

The creation dialog's keyboard focus and scrolling are checked at 760×480; footer
actions remain reachable. English and Chinese native Windows captures are checked
at actual 125% DPI. Both languages also exercise offscreen 100%, 125%, 150% and
200% scale settings. Offscreen tests load installed Windows fonts solely for
rendering QA; production font behavior is unchanged.

## Reproduction and boundaries

In this initialized checkout:

```sh
cmake -P scripts/init-dependencies.cmake
cmake --preset core-release
cmake --build --preset core-release
ctest --preset core-release

# Supported POSIX compiler: application ASan/UBSan.
cmake --preset core-sanitizers
cmake --build --preset core-sanitizers
ctest --preset core-sanitizers

# Fresh source-built pinned Qt desktop configuration.
cmake -DANANARCHIVER_INIT_QT=ON -P scripts/init-dependencies.cmake
cmake --preset desktop-release
cmake --build --preset desktop-release
ctest --preset desktop-release
```

Windows commands can use `scripts/Invoke-Msvc.ps1`. This run reused the existing
source-built pinned Qt 6.10.3 MSVC kit through the explicit developer-Qt option;
archive dependencies were rebuilt from pinned sources in this worktree. MinGW
likewise has an independently GCC-built backend/codecs; Clang-cl uses the compatible
MSVC-built C dependency libraries. Linux archive dependencies were built natively.
Application sanitizer targets do not instrument every codec; the separate ZIP
backend regression build also instruments libarchive itself.

The ZIP abort leak and its separate pinned backend fix are documented in
[the dependency validation](2026-10-07-libarchive-zip-abort.md). The backend commit
is local and has not been published: a fresh remote clone cannot fetch the new
gitlink until that revision is pushed. Application implementation changes were
uncommitted on `codex/m3` at validation time; they were subsequently committed as
`6a1b518` and merged into `main` by `8cdf03c` (PR #3). The 2026-10-08 M4 checkout
recovered the exact backend commit from the earlier local worktree because the
remote still could not serve it; the parent gitlink was not changed.

The validated desktop executable is in `out/build/m3-msvc`. On Windows, launch
it with the exact Qt kit selected by its CMake cache:

```powershell
./scripts/Start-Desktop.ps1 out/build/m3-msvc
```

Use the toolbar's Create archive action or Ctrl+N to add files/folders and start
creation. The launcher changes only its own PATH and does not create a portable
distribution. Its `--smoke-test 500` startup path was also exercised.

macOS build/runtime, Linux GUI, physical screen-reader use, manually operating the
native file pickers, packaged distribution, million-entry/100 GB workloads and
cross-tool interoperability were not exercised. Source identity/metadata checks
detect common mutations but do not create a filesystem snapshot. Codec memory
and a single blocked OS/codec call are not bounded by a hard process sandbox.
Abrupt termination/power loss can leave staging files; crash recovery is outside
M3. An atomic install can succeed before a later directory-durability or staging
cleanup diagnostic fails; the error explicitly identifies the committed state.
