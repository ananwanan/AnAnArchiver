## Reproduction

After a Release desktop build and dependency source initialization:

```powershell
./scripts/Package-Windows.ps1 -BuildDirectory out/build/m5-msvc -SkipBuild -BootstrapInstaller
./scripts/New-WindowsUpgradeFixture.ps1 -PortableDirectory out/artifacts/windows/AnAnArchiver-1.0.0-windows-x64
./scripts/Test-Package.ps1 -BuildDirectory out/build/m5-msvc `
    -PortableArchive out/artifacts/windows/AnAnArchiver-1.0.0-windows-x64.zip `
    -InstallerPath out/artifacts/windows/AnAnArchiver-0.9.0-windows-x64-upgrade-fixture-setup.exe `
    -UpgradeInstallerPath out/artifacts/windows/AnAnArchiver-1.0.0-windows-x64-setup.exe `
    -TemporaryRoot D:/Cache/Codex
```

`m5-msvc` is this run's build directory, not a new required preset. The scripts
accept any matching Release application/superbuild directory. Package and
artifact manifests carry source, tool, version and SHA-256 evidence.

## Boundaries

Installation acceptance redirects the same registry code into a GUID namespace;
it does not change real defaults, UserChoice, application registration or desktop
shortcuts. Actual Explorer menu interaction/default-app selection was not
performed. The 0.9.0 upgrade fixture uses current application binaries with an
older installer product version and obsolete managed files; it verifies installer
transitions, not historical application/data-schema migration.

Linux/macOS deployment code and metadata are implemented, but native builds,
GNOME/KDE/Finder operations, macOS app/DMG runtime, signing/notarization and a
clean external Windows machine/VM were not exercised. Release installer signing
requires the publisher's certificate. Remote CI was not dispatched in this task.
