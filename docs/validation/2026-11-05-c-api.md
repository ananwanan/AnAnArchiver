# 2026-11-05 F1 C ABI

## Scope

Implemented `ananarchiver_c_api` ABI v1 over existing Application services:

- Opaque engine, engine-scoped task IDs, version/feature negotiation, native
  structure sizes, fixed-width fields and explicit Windows calling convention.
- Checked length-delimited UTF-8 requests, structured synchronous/task errors,
  contained exceptions and provider-owned immutable results with matching frees.
- Real worker-based content probing, metadata enumeration, extraction and
  creation, actual writer capabilities, snapshots, cancellation and conflict IDs.
- At most 512 entries per transfer, existing eight-batch backpressure, original
  entry ordinals, bounded request arrays/bytes and existing backend safety limits.
- Immediately invalidated task IDs with background cancel/discard/join; owned
  shutdown worker and explicit final off-UI engine destruction. No callbacks or
  detached workers. Snapshots/batches can outlive task/engine shutdown.
- PIC, Windows exports, ELF/Mach-O export restrictions, installable C header and
  shared library; GUI-free build and superbuild option propagation.

Application changes add allocation-free queue discard for cleanup and password
guards for failed/exceptional task submission. Core parsers, extraction
transactions and compression pipelines remain the existing implementations.

## Environment and dependencies

Verified on Windows x64, MSVC 19.51.36260.0, CMake 4.4.0, Ninja, Release, with
`ANANARCHIVER_BUILD_QT=OFF`. No Qt, Flutter or Dart SDK is required by this build.

`dependency-provenance.json` and `resolved-dependencies.json`.

## Commands and results

Run in an MSVC developer shell (or through `scripts/Invoke-Msvc.ps1`):

```powershell
cmake -S . -B out/build/f1-release -G Ninja `
  -DCMAKE_BUILD_TYPE=Release -DANANARCHIVER_SUPERBUILD=ON `
  -DANANARCHIVER_BUILD_QT=OFF
cmake --build out/build/f1-release --parallel 4
ctest --test-dir out/build/f1-release/application --output-on-failure --parallel 4
```

The full run passed **8/8 CTest suites**, including **118 dependency-tool unit
tests**, the existing Core/archive/extraction/compression/Application regressions,
the C consumer and eight C ABI integration cases. Dependency tests took about
215 seconds. After the final ABI refinements and additional edge assertions,
the library rebuilt without project warnings and all **7/7 native suites**
passed again (`-E '^dependency_tools$'`), in about 2.7 seconds.

The C ABI cases cover malformed Unicode/NUL/null and overflowing inputs, short
and extensible structures, stale/released IDs, real content detection with an
unrelated extension, Unicode paths, duplicate original ordinals, bounded batches,
owned snapshots/errors after engine destruction, invalid/missing archives,
backpressure cancellation, release of active tasks, shutdown while waiting for
metadata/conflict answers, stale/duplicate conflict decisions, explicit empty
selection, implicit-directory selection, password-required/wrong/owned-password
paths, traversal rejection, real ZIP creation/extraction and concurrent polling
with repeated task reclamation.

Additional verification:

- C11 smoke consumer compiles as C and links only the shared C API.
- `dumpbin /exports` reports exactly the 18 declared `aa_*` functions; no C++
  class, STL or backend symbols are exported on Windows.
- `dumpbin /dependents` reports Windows/VC runtime libraries and no Qt, Flutter
  or Dart libraries.
- `cmake --install out/build/f1-release/application --prefix out/install/f1-c-api`
  succeeds, including header, DLL/import library and provenance records.
- A separately compiled C11 consumer using only that installed header/import
  library runs successfully beside the installed DLL (`C ABI consumer passed`).
- The test runtime DLL and built DLL have identical SHA-256 hashes. Test builds
  refresh the DLL even when only its implementation changes.
- `clang-format --dry-run --Werror` passes for new C/C++ files, and
  `git diff --check` passes.
- Public and macOS export lists contain the same 18 names; changed documentation
  links and code fences pass local validation. This checks list consistency,
  not native macOS linker/runtime behavior.

Build outputs and installed smoke artifacts are under ignored `out/`; source
changes were uncommitted during validation. The preserved Qt baseline branch is unchanged.
