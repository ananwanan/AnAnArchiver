# M2 extraction validation — 2026-10-07

M2 implements the entire extraction path: secure request/policies, streaming
payload verification and output transactions, managed cancellable tasks, and
Qt multiselection/destination/password/overwrite interactions.

| Configuration | Result |
| --- | --- |
| Windows x64, MSVC 19.51, pinned backend + source-built Qt 6.10.3 | Build and 8/8 CTest suites passed |
| Windows x64, GCC 16.1, independently GCC-built pinned backend/codecs | Build and 4/4 Core/Application CTest suites passed |
| Windows x64, Clang-cl 22.1, pinned MSVC-built C backend/codecs | Build and 4/4 Core/Application CTest suites passed |
| Ubuntu 24.04 under WSL2, GCC 13.3, native pinned backend/codecs | Debug build with application ASan/UBSan and 4/4 CTest suites passed |

The final Windows extraction suite contains 28 generated regression groups;
POSIX has 26 because Windows junction and sharing-violation cases are specific
to Windows. Archive indexing retains its 16 groups; application tasks contain
15 groups, including cancellable overwrite waits, stale-response rejection,
apply-to-all, shutdown, real byte/speed reporting, and preserving recovery
errors when cancellation is accepted.

Extraction regressions verify ZIP, TAR, TAR.GZ, 7z and raw GZIP; all/selected
ordinals and duplicate names; directory descendants appearing before/after
their header; Unicode and Windows paths beyond MAX_PATH; every overwrite
policy; directory subtree Rename/Skip with relocated links; safe/preserved/
skipped links; traversal, drive/UNC, ADS, DOS aliases, symlink and junction
escapes; existing hardlinks; in-flight ancestor substitution; finite entry,
path/depth, metadata, declared/actual/logical-byte and elapsed limits; CRC,
truncation, unsupported codecs and AES authentication failures; and rollback
on cancellation, corruption and callback exceptions.

The sparse fixture has a 1 MiB logical size but only 13 bytes of data, verifying
both holes and actual progress. A Windows sharing violation deliberately blocks
restoration after cancellation: the result is `CleanupFailed`, the original
backup remains available, and the diagnostic names its recovery directory.
MSVC and Linux exercised native symlink cases. The MinGW standard-library
symlink-creation probe reported unavailable, so creation-only symlink fixtures
were conditionally skipped in that configuration; junction/hardlink and other
security checks still ran.

Production QML tests exercise the Extract action/dialog/button, Ctrl/Shift
selection and Ctrl+A, duplicate ordinals, selected directories, actual ZIP/TAR
extraction, asynchronous overwrite/apply-to-all/cancel, event-loop
responsiveness, encrypted ZIP password retry, input clearing and failure
cleanup. Header-password UI retry uses a synthetic reader; it does not certify
every encrypted format. Supported encryption remains the pinned backend's
capability. Existing plain-text malicious-filename rendering tests still pass.

`qmllint` passed without warnings. English and Chinese dialog screenshots were
checked with the native Windows platform at 125% DPI; additional production
QML flows passed at 100%, 150% and 200% with offscreen rendering. Offscreen
Windows font output was unsuitable for typography review, so native captures
were used. Final project-authored C++ builds were warning-free; previously
compiled Qt-generated QML code emitted upstream Qt C4702 warnings.

The backend source revision was verified against the gitlink:
`8bb3bbdc7b117a1e22086a2260f2087aafa90687`. Qt likewise matches its gitlink
`6417867c2da7aa2b1b94fb9ab084b514fb7009bb`. No dependency/parser changes were
made. Windows reused existing pinned dependency installations; Linux rebuilt
all pinned archive dependencies natively. Sanitizers instrument application
Core/Backend/Application/test targets, not every third-party library.

To reproduce in an initialized source checkout:

```sh
cmake -P scripts/init-dependencies.cmake
cmake --preset core-release
cmake --build --preset core-release
ctest --preset core-release

# Linux/macOS application sanitizer configuration
cmake --preset core-sanitizers
cmake --build --preset core-sanitizers
ctest --preset core-sanitizers

# Pinned desktop Qt build
cmake -DANANARCHIVER_INIT_QT=ON -P scripts/init-dependencies.cmake
cmake --preset desktop-release
cmake --build --preset desktop-release
ctest --preset desktop-release
```

On Windows, use `scripts/Invoke-Msvc.ps1` to initialize the compiler environment.
The new suite names are `extraction` and `qt_extraction`. Changes remain in the
current worktree; they were not committed or pushed.

macOS runtime, physical screen-reader operation, million-entry/100 GB performance
and packaged distribution were not tested. Request budgets protect application
metadata and decoded/logical output work. They do not impose a hard codec/process
RSS ceiling or preempt a single blocked OS/codec call. Power loss/process kill
can leave staging files; this milestone does not provide crash recovery or a
process sandbox. Normal error/cancel rollback failures retain recovery data and
surface their details instead of reporting an ordinary cancellation.
